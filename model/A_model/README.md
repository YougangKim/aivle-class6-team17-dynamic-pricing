# A 파트: 가격 의사결정 파이프라인

## 개요

A 파트는 신선식품 동적 할인 시스템에서 기본수요를 예측하고, 할인 후보를 생성한 뒤, 최적의 할인 정책을 선택하는 가격 의사결정 영역입니다.

A 파트는 다음 세 부분으로 구성됩니다.

- **기본수요 예측 모델 (Base Demand Forecasting Model)**
  - 할인하지 않은 정가 조건의 기본수요를 P10·P50·P90 분위수로 예측합니다.

- **할인 후보 생성 모듈 (Discount Candidate Generation Module)**
  - 재고, 잔여 유통기한, 가격탄력성 및 운영 제약을 고려하여 시간대별 할인 후보 정책을 생성합니다.

- **최적 할인 정책 선택 모듈 (Discount Policy Selection Module)**
  - B Model의 후보별 정책 시뮬레이션 결과를 비교하여 최적의 할인 정책을 선택합니다.

# 기본수요 예측 모델의 학습 구조

| 구분 | 의미 | 사용 시점 |
|------|------|----------|
| 입력 피처 X | 모델이 예측에 사용하는 설명변수 | 모델 학습·검증·예측 |
| 정답 Y | 모델이 학습해야 하는 실제 관측값 | 모델 학습·평가 |

# 기본수요 예측 모델

## 1. 예측 단위

예측 단위는 다음과 같습니다.

```text
점포 × 상품 × 날짜 × 시간
```

예를 들어 특정 점포에서 특정 상품이 특정 날짜의 특정 시간에 정가 조건으로 얼마나 판매될지를 예측합니다.

## 3. 학습 정답 Y

모델의 정답 Y는 `receipt.csv`의 `quantity`를 이용하여 생성합니다.

`receipt.csv`에는 동일한 점포·상품·날짜·시간 안에 여러 구매 건이 존재할 수 있습니다.

예시:

| store_id | product_id | sale_date | sale_time | quantity |
|----------|------------|-----------|-----------|----------|
| S01 | P01 | 12/01 | 18:05 | 1 |
| S01 | P01 | 12/01 | 18:20 | 2 |
| S01 | P01 | 12/01 | 18:47 | 1 |

예측 단위가 점포·상품·날짜·시간이므로, 동일 시간대의 거래를 하나로 합산합니다.

| store_id | product_id | date | hour | sales_qty |
|----------|------------|------|------|-----------|
| S01 | P01 | 12/01 | 18 | 4 |

정답 컬럼은 다음과 같이 정의합니다.

> 모델의 정답 Y는 점포·상품·날짜·시간별 실제 판매수량인 `sales_qty`입니다.  
> 코드에서는 `sales_qty`를 학습용 타깃 컬럼인 `demand_target`으로 사용합니다.

```text
receipt.csv의 quantity
        │
        │ 점포·상품·날짜·시간별 합산
        ▼
sales_qty
        │
        │ 모델 학습용 타깃 컬럼으로 사용
        ▼
demand_target
```

```text
Y = demand_target
  = 점포·상품·날짜·시간별 실제 판매수량(sales_qty)
```

`quantity`를 개별 거래 단위로 직접 사용하는 것이 아니라, 기본수요 예측 모델의 예측 단위에 맞게 시간별 판매량으로 집계하여 사용합니다.

## 4. 단일 LightGBM

단일 LightGBM은 동일한 입력 피처 X와 하나의 정답 Y를 사용하여 P10·P50·P90 분위수 예측 모델을 각각 학습합니다.

### 4.1 입력 X

```text
점포·상품·시간 정보
달력·상권·상품 정보
가격·방문객 정보
재고·유통기한 정보
과거 판매 시계열 피처
```

### 4.2 정답 Y

```text
demand_target
= 점포·상품·날짜·시간별 실제 판매수량
```
하나의 실제 판매수량인 `demand_target`을 공통 정답으로 사용하되, 각 모델의 Quantile Loss 설정을 다르게 하여 P10·P50·P90을 각각 학습합니다.

### 4.3 학습 모델과 예측 결과

| 학습 모델 | 공통 정답 Y | 예 결과 |
|----------|-------------|----------|
| P10 Quantile LightGBM | `demand_target` | `base_demand_p10` |
| P50 Quantile LightGBM | `demand_target` | `base_demand_p50` |
| P90 Quantile LightGBM | `demand_target` | `base_demand_p90` |

각 분위수의 의미는 다음과 같습니다.

| 분위수 | 의미 |
|--------|------|
| P10 | 실제 수요가 이 값 이하일 가능성이 약 10%인 보수적 수요 예측 |
| P50 | 실제 수요가 이 값 이하일 가능성이 약 50%인 중앙 수요 예측 |
| P90 | 실제 수요가 이 값 이하일 가능성이 약 90%인 상단 수요 예측 |

## 5. 2단계 LightGBM

시간대별 판매량에 0이 많이 포함되는 희소수요 특성을 반영하기 위해 2단계 LightGBM 구조로 개선합니다.

### 5.1 1단계: 수요 발생 여부 분류

1단계 모델은 해당 점포·상품·시간에 판매가 발생하는지를 예측합니다.

```text
입력 X
- 단일 LightGBM과 거의 동일한 입력 피처

정답 Y
- demand_occurrence
```

`demand_occurrence`는 다음과 같이 생성합니다.

```text
demand_target = 0
→ demand_occurrence = 0

demand_target > 0
→ demand_occurrence = 1
```

1단계에서는 LightGBM 분류 모델을 학습하며, 실행 결과는 수요 발생 확률입니다.

```text
P(demand_target > 0)
```

### 5.2 2단계: 조건부 판매수량 예측

2단계 모델은 실제 판매가 발생한 행만 이용하여 판매수량을 예측합니다.

```text
학습 대상
- demand_target > 0인 행

입력 X
- 단일 LightGBM과 거의 동일한 입력 피처

정답 Y
- demand_target
```

2단계에서는 판매가 발생했다는 조건에서 판매수량의 P10·P50·P90을 예측합니다.

| 학습 모델 | 학습 대상 | 정답 Y | 실행 결과 |
|----------|----------|--------|----------|
| P10 Quantile LightGBM | `demand_target > 0` | `demand_target` | 조건부 판매수량 P10 |
| P50 Quantile LightGBM | `demand_target > 0` | `demand_target` | 조건부 판매수량 P50 |
| P90 Quantile LightGBM | `demand_target > 0` | `demand_target` | 조건부 판매수량 P90 |

```text
1단계 LightGBM 분류 모델
- 수요 발생 확률 예측
        │
        ▼
2단계 Quantile LightGBM
- 수요 발생 시 판매수량 P10·P50·P90 예측
        │
        ▼
최종 정가 기본수요 P10·P50·P90 생성
```

## 6. 실행 입력

실행 단계에서는 예측 대상 시간의 실제 판매량인 `demand_target`이 아직 존재하지 않습니다.

따라서 학습된 모델에는 예측 시점까지 확인 가능한 X 피처만 입력합니다.

```text
점포·상품·예측 날짜·예측 시간
달력·점포·상품 정보
정가·원가 정보
현재 재고·유통기한 상태
예측 시점 이전의 판매 이력
방문객 및 이벤트 정보
```

> 미래의 실제 판매량인 `demand_target`은 실행 입력에 포함하지 않습니다.

## 7. 예측 결과

기본수요 예측 모델은 정가 조건의 기본수요를 P10·P50·P90으로 출력합니다.

| 출력 | 설명 |
|------|------|
| `store_id` | 예측 대상 점포 ID |
| `product_id` | 예측 대상 상품 ID |
| `date` | 예측 날짜 |
| `hour` | 예측 시간 |
| `base_demand_p10` | 정가 기준 기본수요의 P10 예측값 |
| `base_demand_p50` | 정가 기준 기본수요의 P50 예측값 |
| `base_demand_p90` | 정가 기준 기본수요의 P90 예측값 |

```

기본수요 예측 모델의 실행 결과는 할인 후보 생성 모듈과 B Model의 정책 시뮬레이션에 전달됩니다.

기본수요 예측값은 B Model에서 무할인 판매 규모를 맞추기 위한 기준값으로 사용하며, 구매확률 계산식에 다시 단순히 곱하지 않습니다.

이는 기본수요 예측값과 B Model의 구매확률이 중복 반영되는 것을 방지하기 위함입니다.

# 할인 후보 생성 모듈
구현 완료 후 내부 처리 과정과 세부 내용을 실제 코드에 맞게 업데이트할 예정입니다.

## 1. 입력

할인 후보 생성 모듈은 기본수요 예측 모델의 실행 결과와 현재 운영 상태를 함께 입력받습니다.

| 입력 | 용도 |
|------|------|
| 기본수요 P10·P50·P90 | 향후 정가 기준 판매 규모 확인 |
| 현재 재고 | 남은 영업시간 동안 소진해야 할 수량 판단 |
| 로트별 잔여 유통기한 | 폐기 위험 판단 |
| 정가 및 원가 | 할인 가능 가격 범위 계산 |
| 가격탄력성 | 할인 적용 시 수요 변화 추정 |
| 상품별 최대 할인율 | 상품별 할인 상한 적용 |
| 현재 적용 할인율 | 할인율 역행 방지 |
| 영업 종료까지 남은 시간 | 할인 시작 시점 후보 생성 |
| 기존 할인 정책 | 신규 정책과 비교할 기준 후보로 포함 |
| 운영 제약조건 | 운영 불가능한 정책 제거 |

---

## 2. 내부 처리

모듈은 다음 순서로 후보 할인 정책을 생성합니다.

```text
실시간 POS 판매·재고·유통기한 상태 확인
        │
        ▼
할인 시작 시점 후보 생성
- 즉시 할인
- 일정 시간 후 할인
- 재고·유통기한 위험이 임계치에 도달하는 시점
        │
        ▼
0%~40% 할인율을 1%p 단위로 생성
        │
        ▼
미래 시간대별 할인 경로 조합
        │
        ▼
운영 제약을 위반한 후보 제거
        │
        ▼
유사하거나 효과가 낮은 후보 사전 제거
        │
        ▼
B Model에 전달할 후보 할인 정책표 생성
```

---

## 3. 운영 제약조건

다음 운영 제약조건을 적용합니다.

- 최대 할인율은 40%로 제한합니다.
- 할인율 후보는 1%p 단위로 생성합니다.

```text
0%, 1%, 2%, 3%, ..., 39%, 40%
```

- 할인 적용 가격은 원가 이상이어야 합니다.
- 필요한 경우 최소 마진율 조건을 추가합니다.
- 할인율은 현재 할인율을 기준으로 유지하거나 상승하는 방향만 허용합니다.
- 이미 적용된 할인율이 임의로 낮아지는 정책은 제거합니다.
- 품절 상품에는 할인 후보를 생성하지 않습니다.
- 판매 불가 재고에는 할인 후보를 생성하지 않습니다.
- 유통기한이 만료된 재고에는 할인 후보를 생성하지 않습니다.
- 짧은 시간에 할인율이 반복적으로 변경되지 않도록 최소 유지시간 또는 재변경 제한을 적용합니다.
- 현재 재고와 잔여 유통기한을 기준으로 현실적으로 소진 가능한 범위를 벗어나는 후보는 제거합니다.

---

## 4. 후보 정책 출력

출력은 B Model에서 평가할 **후보 할인 정책 테이블**입니다.

| 출력 | 설명 |
|------|------|
| `policy_id` | 후보 정책 ID |
| `store_id` | 적용 점포 |
| `product_id` | 적용 상품 |
| `date` | 적용 날짜 |
| `hour` | 적용 시간 |
| `dte_min` | 정책을 적용할 최소 잔여 유통기한 |
| `dte_max` | 정책을 적용할 최대 잔여 유통기한 |
| `discount_rate` | 적용 할인율, 0~40 정수 |

하나의 `policy_id`에는 미래 시간대별 할인율 경로가 포함될 수 있습니다.

예시:

| policy_id | hour | discount_rate |
|-----------|------|---------------|
| P001 | 17 | 0 |
| P001 | 18 | 10 |
| P001 | 19 | 20 |
| P001 | 20 | 30 |

# 최적 할인 정책 선택 모듈
구현 완료 후 내부 처리 과정과 세부 내용을 실제 코드에 맞게 업데이트할 예정입니다.

## 1. 입력

다음 두 결과를 함께 입력받습니다.

### 후보 할인 정책

```text
policy_id
점포·상품·날짜
시간대별 할인율 경로
잔여 유통기한 적용 범위
```

### B Model 후보별 시뮬레이션 성과

```text
policy_id
예상 판매량
예상 매출
예상 마진
예상 잔여재고
예상 폐기량
예상 폐기비용
예상 이익
이익 변동성
기존 정책 대비 개선 효과
```

최적 할인 정책 선택 모듈은 B Model의 결과에서 `policy_id`를 선택합니다.

선택된 `policy_id`가 실제로 어떤 시간대별 할인율 경로를 의미하는지 확인하기 위해 할인 후보 생성 모듈의 후보 정책표도 함께 참조합니다.

---

## 2. 정책 선택 기준

최적 할인 정책 선택 모듈은 후보 정책별 목적함수 점수를 계산하여 가장 높은 정책을 선택합니다.

목적함수 예시는 다음과 같습니다.

```text
objective_score
= expected_profit
- risk_weight × profit_variability
- waste_weight × expected_waste_cost
```

- `expected_profit`: 후보 정책의 예상 이익
- `profit_variability`: 반복 시뮬레이션에서 발생한 이익 변동성
- `expected_waste_cost`: 예상 폐기비용
- `risk_weight`: 변동성에 대한 패널티 가중치
- `waste_weight`: 폐기비용에 대한 패널티 가중치

---

## 3. Rolling Horizon 운영

최적 할인 정책 선택 모듈이 전체 미래 할인 경로를 선택하더라도 운영 시점에는 현재 시간에 해당하는 할인율만 적용합니다.

```text
현재 상태 확인
        │
        ▼
미래 할인 경로 평가
        │
        ▼
현재 시간의 할인율만 적용
        │
        ▼
실제 판매 결과 반영
        │
        ▼
재고·유통기한 상태 갱신
        │
        ▼
다음 시간에 후보 정책 재평가
```

이를 통해 실제 판매량과 재고 상태 변화에 따라 할인 정책을 지속적으로 수정할 수 있습니다.

---

## 4. 최종 정책 출력

최적 할인 정책 선택 모듈의 출력은 A 파트의 최종 출력입니다.

| 출력 | 설명 |
|------|------|
| `selected_policy_id` | 선택된 최적 후보 정책 |
| `store_id` | 적용 점포 |
| `product_id` | 적용 상품 |
| `date` | 적용 날짜 |
| `recommended_start_hour` | 권장 할인 시작 시점 |
| `hour` | 적용 시간 |
| `recommended_discount_rate` | 시간대별 권장 할인율 |
| `expected_sales_qty` | 선택 정책의 예상 판매량 |
| `expected_revenue` | 선택 정책의 예상 매출 |
| `expected_margin` | 선택 정책의 예상 마진 |
| `expected_waste_qty` | 선택 정책의 예상 폐기량 |
| `expected_profit` | 선택 정책의 예상 최종 이익 |
| `risk_or_variability` | 선택 정책의 시뮬레이션 변동성 |
| `improvement_vs_existing` | 기존 정책 대비 개선 효과 |

최적 할인 정책 선택 모듈이 예상 판매량·마진·폐기량·이익을 직접 새로 예측하는 것은 아닙니다.

B Model이 계산한 후보별 성과 중 최적 할인 정책 선택 모듈이 선택한 `policy_id`에 해당하는 값을 최종 할인 정책과 함께 출력합니다.

예상 성과를 최종 출력에 포함하는 이유는 다음과 같습니다.

- 해당 할인 정책을 선택한 근거를 설명할 수 있습니다.
- 기존 할인 정책과의 성과 차이를 비교할 수 있습니다.
- 관리자 알림 여부를 판단하는 근거로 사용할 수 있습니다.
- 대시보드에서 예상 폐기 감소와 이익 개선 효과를 제공할 수 있습니다.
